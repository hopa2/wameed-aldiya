# منظومة وميض الضياء: لوحة تحكم موحدة + وكلاء محليون

كل شيء يعمل على اللابتوب الموجود، بلا أي خدمة مدفوعة:

| الجزء | أين يعمل | ماذا يفعل |
|---|---|---|
| **Postgres** (الموجود) | Docker على اللابتوب | مخطط جديد اسمه `wameed` داخل قاعدة `n8n` نفسها: الإعدادات، الوكلاء، السجل، **بوابة التنفيذ** |
| **n8n** (الموجود) | Docker على اللابتوب | 6 workflows: تشغيل الوكلاء، التنفيذ، الإشعار، المجدول، فحص الصحة، واتساب الوارد |
| **Ollama** (الموجود) | Windows مباشرة على كرت الشاشة | `qwen3:8b` لكل الوكلاء، و`qwen3:14b` لوكيل الإعلانات كما هو |
| **لوحة التحكم** (جديد) | Docker على اللابتوب، المنفذ 8080 | صفحة عربية للجوال والكمبيوتر: الحالة، الموافقات، الوكلاء، السجل، الإعدادات |
| **WAHA** (الموجود) | Synology | يبقى كما هو. n8n يرسل له الردود المعتمدة فقط |
| **تيليجرام** | بوتك | إشعار لكل طلب موافقة وموجز الصباح والتنبيهات |

```
 المالك ⇄ لوحة التحكم (Tailscale) ─┐                    ┌─► تيليجرام (إشعارات)
                                     ▼                    │
 المجدول كل 5 د ─► wameed-run ─► Ollama (qwen3) ─► Postgres: بوابة التنفيذ ─┬─ تلقائي ─► wameed-execute ─► WAHA / تيليجرام
 WAHA (رسالة عميل) ─► wameed-waha ─┘                    (الحواجز هنا)       └─ يحتاجك ─► اللوحة: موافقة/رفض ─┘
 وكيل الإعلانات (workflow خاص) ─► wameed-run بـ envelope جاهز ─► يُسجل في نفس اللوحة
```

## الفكرة الأساسية: الحواجز في قاعدة البيانات، لا في البرومبت

كل إجراء يقترحه أي وكيل يمر على الدالة `wameed.gate_check` في Postgres، فلا n8n ولا النموذج يستطيعان تجاوزها:

- **ممنوع نهائيًا:** إنشاء أو تعديل أو حذف فاتورة مبيعات، حذف سجل، إرسال جماعي، التزام مالي.
- **كل وكيل له صلاحياته فقط:** وكيل المبيعات والمالية قراءة فقط، ووكيل المخزون وحده يقترح أمر شراء.
- **أمر الشراء:** لمورد معتمد فقط، وتعيد البوابة حساب الإجمالي من البنود (لو أخطأ النموذج في الجمع يُرفض)، وسقف 3,000 للطلب و10,000 لليوم، ويُعاد فحص سقف اليوم لحظة موافقتك.
- **التسعير:** لا هامش تحت الحد الأدنى للفئة، ولا زيادة فوق 10% دفعة واحدة، ولا تخفيض.
- **واتساب:** لا روابط إلا رابط المحل، ولا مجموعات، وحد 30 ردًا في الساعة. وفي **وضع الظل** لا يصل أي رد لعميل إلا بموافقتك.
- **فترة التجربة** (`dry_run_until`، 14 يومًا من التثبيت): الإجراءات التلقائية تُسجل «كان سينفذ» ولا تُنفذ. ما توافق عليه أنت يُنفذ، والإشعارات تصل.
- **الإيقاف** (زر «إيقاف الكل»): لا تشغيل ولا تنفيذ ولا موافقة حتى تستأنف.
- **المهلة:** طلب لم تقرر فيه خلال 4 ساعات = مرفوض.
- **لا تنفيذ مرتين:** التنفيذ يحجز الإجراء أولًا (`claim_action`).

اختبار البوابة (أكثر من 20 حالة) في `db/tests/gate_test.sql`، ويعمل داخل معاملة تتراجع فلا يترك أثرًا.

## التثبيت (مرة واحدة، حوالي 10 دقائق)

المتطلب: تثبيت وكيل الإعلانات تم، أي أن `C:\wameed\docker-compose.yml` و`.env` موجودان وn8n يعمل.

```powershell
cd C:\wameed
git clone https://github.com/hopa2/wameed-aldiya.git
powershell -ExecutionPolicy Bypass -File .\wameed-aldiya\system\scripts\install.ps1
```

السكربت: يضيف للـ `.env` سرًا عشوائيًا وكلمة سر للوحة (لا يكتب فوق الموجود)، ويشغّل `docker compose up -d --build`، ويطبّق مخطط `wameed`، ويستورد الـ workflows والـ Credentials إلى n8n ويفعّلها، ثم يطبع كلمة سر اللوحة مرة واحدة.

بعده:

1. ضع توكن البوت في `C:\wameed\.env` على السطر `TELEGRAM_BOT_TOKEN=` (بالمفكرة، لا في أي محادثة)، ومفتاح WAHA في `WAHA_API_KEY=` إن كان مفعّلًا، ثم أعد تشغيل السكربت.
2. افتح `http://127.0.0.1:8080` ← **الإعدادات**: `owner_chat_id`، و`waha_url` (عنوان Synology في Tailscale مع `:3000`)، و`waha_session`.
3. **من الجوال:** على اللابتوب شغّل `tailscale serve --bg --https=8443 http://127.0.0.1:8080`، وثبّت تطبيق Tailscale على جوالك، ثم افتح `https://<اسم-اللابتوب>.<tailnet>.ts.net:8443/`. هذا داخل شبكتك الخاصة فقط، وليس Funnel. ضع الرابط نفسه في `dashboard_url` ليظهر في إشعارات تيليجرام.
4. **الموردون:** أضف مورديك المعتمدين وأرقام واتسابهم من الإعدادات.

**التحديث لاحقًا:** `git -C C:\wameed\wameed-aldiya pull` ثم أعد تشغيل السكربت.

## ما الذي يتغير على جهازك بالضبط

- خدمتان جديدتان في Docker: `wameed-dashboard` (على `127.0.0.1:8080` فقط) و`wameed-migrate` (يعمل ثوانٍ ويخرج).
- n8n نفسه: 3 متغيرات بيئة جديدة، ومجلد المنظومة مقروء داخله على `/wameed`. لا تغيير في الصورة أو المنافذ أو قاعدة n8n.
- 6 workflows جديدة بأسماء تبدأ بـ «وميض |»، و4 Credentials بأسماء تبدأ بـ «Wameed». **workflows وكيل الإعلانات لا تُلمس.**
- webhooks جديدة: `/webhook/wameed-run` و`-execute` و`-notify` و`-waha`. كلها تطلب الترويسة `x-wameed-token`، فهي محمية حتى لو وصلها أحد عبر Funnel.
- النسخة الليلية `pg_dump` الموجودة تشمل مخطط `wameed` تلقائيًا لأنه داخل نفس القاعدة.

## ربط وكيل الإعلانات باللوحة (اختياري، دقيقتان)

في نهاية workflow الإعلانات، بعد التنفيذ، أضف عقدة HTTP Request:

- POST `http://localhost:5678/webhook/wameed-run`، والمصادقة Header Auth بالـ Credential «Wameed Hook Token».
- Body:

```json
{ "agent": "google_ads_agent", "trigger": "external",
  "envelope": { "...": "رد الوكيل كما هو", "actions": [ { "type": "add_negative_keyword", "already_executed": true, "...": "..." } ] } }
```

`already_executed: true` يعني «نفّذته ضمن سقوفي، سجّله فقط»، ومسموح لوكيل الإعلانات وحده.

## نقل خدمة العملاء على واتساب (لاحقًا، عند نقل الوكلاء من Synology)

الـ workflow جاهز ومفعّل على `/webhook/wameed-waha`، لكن WAHA ما زال يرسل لـ n8n القديم، فلا يصله شيء الآن. عند النقل (الخطوة 0 في ملف وكيل الإعلانات):

1. اربط منفذ n8n بعنوان اللابتوب في Tailscale كما في ذلك الملف.
2. في جلسة WAHA غيّر الـ webhook إلى `http://<IP-اللابتوب-في-Tailscale>:5678/webhook/wameed-waha` مع الحدث `message` وترويسة مخصصة `x-wameed-token` بنفس قيمة `WAMEED_HOOK_TOKEN`.
3. أرسل رسالة تجريبية من جوال آخر، وستظهر في اللوحة كطلب موافقة (وضع الظل).

## البيانات: ما ينقص لتعمل الوكلاء بأرقام حقيقية

الوكلاء تقرأ أرقامها من جداول `wameed.sales_daily` و`stock_items` و`receivables` و`suppliers` و`kv_metrics` و`staff`. **هذه الجداول فارغة حتى تُربط مزامنة Manager.io**، وإلى ذلك الحين يقول كل وكيل «غير متوفر» ولا يخترع رقمًا. الربط يحتاج تأكيد إصدار Manager عندك ومفاتيح API2 (انظر «ما يلزم تأكيده» أدناه)، وهو الخطوة التالية.

ويمكن لأي workflow قديم على Synology أن يرسل بياناته المحسوبة مباشرة: `POST /webhook/wameed-run` مع `{ "agent": "inventory_agent", "input": { "low_stock": [...] } }`.

## ما يلزم تأكيده من جهازك

لم أستطع الوصول للابتوب من هنا، فبنيت على الإعدادات المعروفة من الملفات السابقة. تأكد من هذه قبل التثبيت:

1. **هل نُفّذ تثبيت وكيل الإعلانات؟** أي هل `C:\wameed\docker-compose.yml` موجود بخدمتي `postgres` و`n8n` ومستخدم القاعدة `wameed` وقاعدة `n8n`؟ (السكربت يتوقف بوضوح إن لم تكن.)
2. **إصدار n8n:** المنظومة مبنية ومختبرة على n8n 2.46. إن كان عندك 1.x فقد تحتاج تحديث n8n أولًا. ملاحظة: n8n الحديث ينبّه أن Postgres 16 «خارج النطاق المدعوم» ويعمل بدعم توافق، والترقية لـ 17 مهمة منفصلة لا أنصح بها الآن.
3. **مواصفات اللابتوب:** الملفات تذكر مرة RTX 4060 8GB و16GB رام، ومرة 32GB رام. أي منهما صحيح؟ `qwen3:8b` يكفيه الاثنان.
4. **WAHA:** عنوان Synology في Tailscale، واسم الجلسة (`default`؟)، وهل `WHATSAPP_API_KEY` مفعّل.
5. **تيليجرام:** هل workflow الإعلانات يستخدم Telegram Trigger (أوامر مثل `/ads_undo`)؟ المنظومة هنا **لا** تضيف Trigger حتى لا تتعارض معه (تيليجرام يسمح بـ webhook واحد لكل بوت)، فالموافقة من اللوحة.
6. **Manager.io:** نسخة Desktop أم Server؟ وهل API2 مفعّل؟ وهل workflows القديمة على Synology متصلة به فعلًا؟
7. **Tailscale على جوالك:** للوصول للوحة من خارج البيت.
